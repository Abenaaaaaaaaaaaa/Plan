## 1. 背景、目标与非目标

### 1.1 背景

v1.0 是一套 8 屏 UX 流程稿（首屏空态、新建计划、计划列表、计划详情、执行记录、计时、日历汇总、我的）。现状稿的流程主线可以走通，但存在三类结构性问题，直接导致结论不可信、数据不可对账：

1. **同一屏内数字自相矛盾**。v1.0 计划详情屏同时展示「当前执行进度 10.23%」「执行计划天数 57天/365天」「完成计划天数 26天/365天」「距离结束 275天」。按 365 天反推 10.23% 应约为 37 天，与 26、57 均不符；57 + 275 = 332 也不等于 365。没有唯一口径，任何进度展示都无法被用户验证。
2. **"每天必做"与"区间内任意天执行"两种产品定义混用**。列表卡片的「距离结束 275天」暗示每天都欠账，记录面板的两态图例（完成 100% / 执行但未完成）又暗示每天都要交代，而产品实际允许任意天执行。
3. **计时不可靠**。计时页只有一个「开始/暂停」合并按钮，无本次/今日累计回显；无跨天规则；删除为永久删除且无二次确认与撤销（现状稿自己写明"数据无法恢复"）。

### 1.2 目标（可观察，不含量化承诺）

- **可对账**：任一计划在任意时刻，完成度、已执行天数、达标天数、应完成/已投入/落后三组数字必须能被同一套公式互推，用户可用手算验证。
- **可完成**：用户从"打开小程序"到"开始为某个计划计时"不超过 2 次点击（点卡片进详情 → 点底部「开始计时」）。
- **可恢复**：计时在切后台、锁屏、杀进程三种中断下都不丢失已发生的有效时间，重进计时页按时间戳自动续算（跨零点拆分与心跳结算见 §12.3 Q6）。
- **可追溯**：每条时长记录能回答"哪一天、多少分钟、是计时还是补录"；本期不记录具体起止时刻与跨天拆分来源。

### 1.3 非目标（本期明确不做）

- 不做"每天必做/连续打卡/断签惩罚"类机制（与"区间内任意天执行"定义冲突）。
- 不做社交、排行、计划分享、模板市场。
- 不做提醒推送与订阅消息（见 §4 范围）。
- 不做多端同步的账号体系（本期按设备本地存储实现，不做登录态冲突合并）。

### 1.4 平台与实现形态（v2.1 新增）

| 项 | 结论 |
|---|---|
| 交付形态 | **原生微信小程序**（非 H5、非 web-view 嵌套）。原 H5 原型保留于仓库根 `index.html`，仅作设计参照，不作为交付物 |
| 工程结构 | 页面根目录即 `app.json` 所在目录；`pages/{list,calendar,detail,timer,form,manual,me}` + `utils/{date,store,calc}.js` |
| 尺寸基准 | 设计稿 **750 × 1624**，全量使用 `rpx`（750rpx = 屏宽），字号体系：正文 30rpx、次级 26rpx、标题 40rpx、主数字 88rpx、主按钮高 100rpx |
| 日期基准 | **全部取设备真实系统日期**（`new Date()`），不写死演示日期。所有示例数据、状态判定、日历定位、补录上限均随真实日期滚动 |
| 演示数据 | 小程序版**不内置 seed 数据**，首次启动为空态；H5 原型中的示例数据已按相对今天的天数生成，仅用于回归演示 |
| 存储 | 本地 `wx.setStorageSync`，按微信账号隔离（详见 §9.4），无自建后端、无云开发 |

## 2. 目标用户与核心场景

### 2.1 目标用户

**以"一段周期内的累计投入"为目标的自学者**，典型是备考、技能学习、语言学习、写作/练习类长期投入。他们的特征：

- 计划周期以月/季/年计（30–365 天），不按"每日打卡"计。
- 允许某几天完全不学（工作忙、出差），但不能接受"断签清零"。
- 关心两件事：**总共投了多少**（累计时长）、**现在落后没有**（应完成 vs 已投入）。

### 2.2 核心场景（P0 旅程）

| 场景 | 触发 | 用户动作序列 | 完成证据 |
|---|---|---|---|
| **S-A 首次建计划并开始** | 首次打开小程序 | 计划页空态 → 「新建第一个计划」→ 填名称/每日目标/区间 → 保存 → 列表出现该卡片 → 点卡片进入详情 → 底部「开始计时」 | 列表卡片显示「今日 0 / 60 分钟 · 未达标」，计时页计时环开始走字 |
| **S-B 日常学习（高频）** | 想起要学 | 打开小程序落在计划页 → 点目标卡片进入详情 → 「开始计时」→ 「结束」→ Toast | Toast 显示「本次 00:12:00，已计入今天」，回到详情后完成度与今日数字同步更新 |
| **S-C 中场休息** | 学习被打断 | 计时页「暂停」→ 做别的事 → 回来「继续」→ 「结束」 | 暂停期间不计入任何数字；恢复后计时环从暂停值继续 |
| **S-D 忘记计时** | 想起来昨天学过但没计时 | 详情/记录面板 → 「手动补录」→ 选日期 + 填分钟 → 保存 | 记录面板与日历上该日出现"补录"标识，完成度按补录后重算 |
| **S-E 复盘欠账** | 月底/周末 | 计划页 → 卡片（看到「累计 100h / 目标 365h」）→ 详情 → 记录面板 → 日历 | 辅助指标行显示「应完成 120h / 已投入 100h / 落后 20h」；记录面板能定位到具体哪几天没有记录 |
| **S-F 计划结束** | 区间走完 | 打开小程序 | 卡片徽标变「已结束」或「已过期」；详情底部主按钮变「再建一个」；可导出记录 |

### 2.3 关键约束（来自现状）

用户已有的一批计划（v1.0 的 A/B/C 计划）为 mock 数据。小程序版**不内置任何 mock 数据，首次启动为空态**，本期**不做数据迁移**；用户从「新建第一个计划」开始。H5 原型保留的示例数据仅用于回归演示，不作为线上数据（见 §1.4）。

## 3. 名词与计算口径（全文档唯一口径）

> 本章是全文档唯一的计算定义来源。功能章节只引用名称，不重复定义。所有示例数字都由本章公式反推得到，见 §3.6。

### 3.1 名词

| 名词 | 定义 |
|---|---|
| **计划 plan** | 一段固定区间内、以一个每日目标时长为基准的投入容器。区间固定后不再自动延长。 |
| **计划天数 plan_days** | 计划的容量天数，用于计算目标总量。 |
| **每日目标 targetMin** | 用户为每个"有效日"设定的目标分钟数（实现字段 `targetMin`）。 |
| **目标总量 targetTotal** | `targetMin × plan_days`，即完成度的分母。 |
| **有效片段 segment** | 一次计时结束或一次补录产生的记录，归属单一日期。本期不做跨零点拆分，一条片段可覆盖跨零点时段（见 §12.3 Q6）。 |
| **累计有效分钟 accumulated** | 某计划全部片段分钟数之和，即完成度的分子（实现不做窗口二次过滤，见 §3.3）。 |
| **完成度 completion** | `accumulated / targetTotal`，唯一百分比指标。 |
| **已执行天数 active_days** | 有任一有效片段（>0 分钟）且在计划区间内的天数。 |
| **达标天数 met_days** | 当日累计分钟 ≥ targetMin 且在区间内的天数。 |
| **已过天数 elapsed_days** | 从计划开始日到今天（含今天）的天数，上限为 plan_days。 |
| **应完成 due_min** | `elapsed_days × targetMin`，滚动口径，只用于辅助指标。 |
| **落后 gap_min** | `max(0, due_min - accumulated)`，只用于辅助指标。 |
| **补录 manual** | 用户手工填入的历史时长，`source = manual`，在执行记录与汇总日历以蓝点可辨识。 |

### 3.2 日期口径（唯一，已锁定）

- **计划统计窗口 = `[开始日期, 结束日期]`**，即**开始日与结束日均计入**。
- **计划天数 = 结束日期 − 开始日期 + 1**（日差 + 1）。

由此，`2026-11-01 → 2027-10-31` 记为 **365 天**，目标总量 `1h × 365 = 365h`。

> 口径提示：`2026-11-01 → 2027-10-30` 只有 **364 天**，不得用作示例。本口径已由产品拍板锁定，全文档示例与验收数字均基于"含首尾"计算，不再保留第二套算法（剩余风险见 §12.2 R1）。

### 3.3 完成度

```
accumulated = Σ segment.min        （segment.planId = 本计划）
targetTotal = targetMin × plan_days
completion  = accumulated / targetTotal               // 不截断
展示值       = 保留 1 位小数，四舍五入
```

> v2.1 实现说明：片段在写入时已受计划区间约束（补录日期限定在 `[start, min(today, end)]`，计时结算日通常落在区间内），因此 `accumulated` 直接对计划全部片段求和，**读取时不再按日期窗口二次过滤**。跨零点等极端情况下的区间外片段仍会计入累计（见 §12.3 Q6）。

- **不为零保护**：`targetTotal` 恒 > 0（每日目标最小 1 分钟、计划天数最小 1 天），不存在除零。
- **超额**：`completion > 100%` 时，**数字继续上涨**（可显示 109.6%），**进度条填充封顶 100%**，进度条右侧增加文字「已超额 35h」。
- **分母固定**：`targetTotal` 在计划创建时确定，中途**不随日期流逝增长**。修改每日目标或区间后按新值重算（见 §3.7）。

### 3.4 已执行天数与达标天数

```
active_days = COUNT(DISTINCT date)  where day_sum > 0           且 date ∈ [start, end]
met_days    = COUNT(DISTINCT date)  where day_sum ≥ targetMin   且 date ∈ [start, end]
```

约束（可作为单元测试断言）：

```
met_days ≤ active_days ≤ plan_days
completion ≠ met_days / plan_days        // 任意天可超额，两者不等价，禁止互相换算展示
```

### 3.5 应完成 / 已投入 / 落后（B 方案辅助指标）

```
elapsed_days = min(plan_days, 今天 − 开始日期 + 1)      // 今天在窗口内时按日累计
due_min      = elapsed_days × targetMin
invested_min = accumulated                              // 与完成度分子同源，必须一致
gap_min      = max(0, due_min − invested_min)
```

- 三者与主进度**同屏展示但视觉次级**（主进度在上，辅助指标在其下一行，字号小于主数字）。
- **主进度不因辅助指标倒退**：`completion` 只增不减（除用户主动改目标/区间）。
- `gap_min = 0` 时该行显示「已跟上」，不显示 0h。

### 3.6 唯一示例数据集（全文档复用，必须可互推）

| 项 | 值 | 反推校验 |
|---|---|---|
| 计划区间 | 开始日 = `今天 − 119 天`，结束日 = `开始日 + 364 天` | 含首尾；v2.1 起不再写死绝对日期 |
| 计划天数 | **365 天** | 日差 + 1 |
| 每日目标 | **60 分钟（1 小时）** | — |
| 目标总量 | **365 小时（21,900 分钟）** | 60 × 365 |
| 今天 | **计划第 120 天**（相对今天推算，随真实日期滚动） | 开始日当天算第 1 天 |
| 已过天数 | **120 天** | 今天 − 开始日 + 1 |
| 应完成 | **120 小时** | 120 × 60min |
| 累计有效分钟 | **6,000 分钟（100 小时）** | 见下 |
| 完成度 | **27.4%** | 6000 / 21900 = 27.397% → 27.4% |
| 已执行天数 | **80 天** | 60 达标天 + 20 未达标天 |
| 达标天数 | **60 天** | 60 × 90min = 5,400min |
| 未达标天数 | **20 天** | 20 × 30min = 600min |
| 累计校验 | 5,400 + 600 = **6,000 分钟** | ✅ |
| 落后 | **20 小时** | 120h − 100h |

> v2.1 修订：示例数据不再绑定 `2027-02-28` 等绝对日期。H5 原型中的 7 个计划与全部计时片段改为**以真实今天为锚点、按相对天数生成**（如 A计划从今天前 119 天开始，今天恰为第 120 天），从而保证任何一天打开演示都是"进行中 + 27.4%"的同一组可互推数字。小程序版无 seed 数据，本条仅约束原型与验收算例。

**互推关系（评审时可现场验算）**：`27.4% × 365h ≈ 100h`；`6,000min ÷ 60min = 100h`；`60天×1.5h + 20天×0.5h = 100h`；`120h − 100h = 20h`。

> 该数据集覆盖"超额与不足混合"的真实分布（60 天超额、20 天不足、40 天空白），因此 v1.0 的三个矛盾数字在本数据集下**不可能再出现**。

### 3.7 目标/区间变更后的口径

- 修改 `targetMin` 或 `start`/`end` 后，`targetTotal` 重算，`completion` 立刻按新分母计算（会跳变）。
- **v2.1 起无变更确认弹窗**：保存即生效（见 §6.2）。
- 仅当 `targetMin` 变化时递增 `targetVersion` 并写入 `changedAt`，详情页显示一行灰字「目标已于 YYYY-MM-DD 调整（第 N 版）」，避免用户误判为数据出错。
- 编辑时若 `start` 晚于 `end`，结束日自动顺延为开始日 + 364 天。
- `start` 不得早于该计划已有记录最早日期的校验**本期未实现**（见 §12.3 Q8）。

### 3.8 舍入与单位

- 计时单段分钟数：`min = Math.round(sec / 60)`（**四舍五入**）；不足 30 秒得 0，提示「不足 1 分钟，本次未计入」且不落库。
- 补录分钟数为用户输入的整数（1–1440）。
- 所有汇总（今日、累计、完成度）均以**整分钟**相加后计算，不允许先转成小时再相加（避免 0.5833h 类精度堆积）。
- 展示：`< 60` 分钟显示为 `Nmin`，否则保留 1 位小数显示 `X.Xh`（见 [date.js](file:///workspace/utils/date.js) 的 `hLabel`）。

## 5. 信息架构与导航

### 5.1 结构

```
Tab 根 1  pages/list              计划页（列表 / 空态，同一路由）
   ├─ pages/form                新建 / 编辑计划
   ├─ pages/detail              计划详情
   │    ├─ 顶部分段 Tab「计划概况」  S5 主体（整屏视图 1）
   │    ├─ 顶部分段 Tab「执行记录」  S6（整屏视图 2，非页内第 4 块）
   │    ├─ pages/manual         手动补录（从详情/记录面板/日历进入）
   │    └─ pages/timer          计时页（独立页面，navigateTo）
   └─ 左滑操作区（置顶 / 删除）+ 删除确认弹窗

Tab 根 2  pages/calendar          汇总页（月度日历）

独立页    pages/me                我的（从计划页右上「我的」进入，有返回）
          用户协议 / 隐私政策      「我的」页内弹层（sheet），不单独占页面
```

> v2.1 修订：计时由「半透明覆盖层」改为**独立页面** `pages/timer`，避免自绘返回逻辑与系统手势叠加；协议与隐私由独立页改为**页内弹层**，减少页面栈层级。

### 5.2 导航规则

| 规则 | 说明 |
|---|---|
| Tab 根不带返回 | 计划页与汇总页是 `switchTab` 页面，**不渲染返回按钮** |
| S1 不是独立页 | 首屏空态是计划页的**空态渲染分支**（同一路由、同一 Tab、同一底部栏）。空态下的「新建第一个计划」与列表态工具栏 `＋` 是**同一个 action**，全产品只有一个"新建计划"入口 |
| S6 不是独立页 | 执行记录是详情页的**第二个整屏视图**，由导航栏正下方的顶部分段 Tab 切换；**不能做成页内下方的内嵌面板**（首屏看不到，会被误判为切换失效），也**不带底部主按钮**（全页主按钮只在 S5 底部固定栏出现一次） |
| S7 是独立页 | 计时页由 `navigateTo` 打开，**进页面栈**；实时计时依赖 `startedAt` 绝对时间戳，因此切后台/锁屏/回前台均按时间戳续算，不依赖常驻定时器（见 §8.3） |
| 汇总页手势 | 日历区域**支持左右滑动切月**，阈值 ±55px 且横向位移需大于纵向 1.5 倍，避免与页面纵向滚动冲突；顶部 ‹ › 与「本月」仍保留，双入口并行 |
| 返回仅存在于 | 计划表单、计划详情、计时页、我的、补录页 |
| 层级深度 | 最深路径：计划页 → 详情 → 补录页 = 3 层，满足小程序栈限制 |

> **v2.1 实现修订**：导航栏改用**小程序原生导航栏**，计划名通过 `wx.setNavigationBarTitle` 设置；计划级动作入口 `···` 置于顶部分段 Tab 行右端，点开 ActionSheet「编辑计划 / 置顶（取消置顶）/ 删除计划」。原「⋮ 药丸与胶囊安全区距离」的自绘方案不再适用，胶囊避让由平台导航栏保证。
> 计时相关文案中的「计时层」统一按「计时页」理解（`pages/timer`）。
> 计划概况在本期进一步简化为：状态徽标 + 置顶标 → 大号完成度数字（右侧显示累计/目标，超额时追加「已超额 Xh」）→ 进度条 → 应完成/已投入/落后 三项横排 → 今日条 → 每日目标|计划区间|已执行|达标 四格 → 底部说明行。

> **v2.1 导航与动作入口结论**：计划名交给原生导航栏（`wx.setNavigationBarTitle`），计划级动作（编辑 / 置顶 / 删除）统一收敛到顶部分段 Tab 行右端的 `···`，两个 Tab 下都可达。放弃自绘导航栏与 `⋮` 药丸的原因：小程序页面无法覆盖系统胶囊，自绘避让在窄机型上仍可能压住胶囊；原生导航栏由平台保证安全区，返回手势与页面栈天然一致。
> 「导出记录」不放详情页，统一在「我的」页，避免同一页面出现并列的多个计划级动作。

> **设计理由（评审问题 1 · 切换可见性）**：v1.0 把「执行记录」做成页面内第 4 块的内嵌 Tab，用户点「执行记录」时首屏（可视区顶部）仍是块1–块3，只有向下滚动才看到内容，"点了没反应/切换失效"是必然误判。改为导航栏正下方的顶部分段 Tab 后，两个 Tab 是**互斥的整屏视图**（不是滚动定位）：切到「执行记录」时首屏第一行就是图例、紧接着当月网格，内容差异在同一屏内肉眼可辨。
> **设计理由（评审问题 1 · 唯一主操作）**：今日条右侧不再放「开始计时」，避免与底部固定栏形成同名双入口。保留底部固定栏（拇指热区、与 S2/S7 的底部主操作位置一致），今日条降级为纯数字展示。详情页底栏恒为「开始计时」；进入计时页后由 session 状态呈现「暂停 / 继续 / 结束」，运行态不在详情页重复表达。

#### 6.3.2 字段与控件

| 位置 | 数据来源 | 可编辑 |
|---|---|---|

### 6.4 FR-S6 执行记录（顶部分段 Tab 的第二视图）

#### 6.4.1 目的

回答"哪几天做了、做了多少、是否达标、是否补录"。它是唯一能把"落后 20h"落到具体日期的界面。

#### 6.4.2 页面结构

> 承载形式：本视图是 S5 详情页的**整屏第二视图**（顶部分段 Tab「执行记录」），不是页内第 4 块的内嵌面板。切到该 Tab 后，**首屏（不滚动）必须是「图例 + 当月月份块」**，不做折叠、不做「展开更多」。

```
[ 顶部分段 Tab ]  计划概况 ｜ 执行记录（选中）        ← 紧贴导航栏，首个像素即为切换控件
[ 图例 ]  [■ 达标]  [■ 有记录未达标]  [■ 无记录]  [● 含补录]
[ 补录入口行 ]  区间外显示为空（左，次要）        ＋ 手动补录（右，可点）
[ 当月月份块 ]  真实当月（随系统日期）
     一二三四五六日（真实周对齐，每格带日期数字）
     每格：状态底色 + 当日分钟（如「90m」）
[ 月份块 ]  上一个月 …
（连续倒序，最多回溯 12 个月，可上下滚动）
```

#### 6.4.3 规则

- **三态**：`day_sum ≥ targetMin` → 达标（绿）；`0 < day_sum < targetMin` → 有记录未达标（黄）；`day_sum = 0` → 无记录（灰）。
- **补录标识**：该日存在 `source = manual` 片段时，格内右下角加 **10rpx 蓝点**（与执行记录视图的补录圆点同义），点开日详情可见来源为「补录」。
- **手动补录的输入与按钮（v2.1 实现）**：
  - 补录日期使用原生 `picker mode="date"`，可选范围 **`[计划开始日, min(今天, 计划结束日)]`**，未来日期与区间外日期不可选。
  - 时长输入为单行数字键盘输入框，标题「时长（分钟）」，**范围 1–1440 分钟**（超出时 Toast「请输入 1–1440 之间的分钟数」并拒绝保存）。
  - 保存入口为页面底部通栏主按钮「保存补录」（与其他页主按钮同规格）；**本期不做实时中文预览与单位后缀控件**。
  - 保存成功后 Toast「已补录」，400ms 后返回上一页。
- **区间外**：`date` 不在 `[start, end]`（含首尾）的格子显示为空，不参与天数统计（累计分子见 §3.3 实现说明）。
- 月份必须**连续倒序**（v1.0 出现 12月→11月→9月跳月，缺 10 月）；最多回溯 12 个月。
- 单格可点击 → 日详情弹层：列出该日全部片段（来源 + 分钟）与当日合计；在可补录日期范围内提供「补录这一天」。
- **本期不支持修正/删除已有片段**：补录一律追加新的 `manual` 片段，日合计与完成度按累加重算（修正能力见 §12.3 Q6）。
- 视觉折算：月度块内每天一格，与真实周对齐；v1.0 的"9 列 × 3 行"不对应任何真实月份，无法定位到日。

| 情况 | 表现 |
|---|---|


> **v2.1 设计修订（高亮条取代微进度条）**：原方案用「1–2 字标识 + 3px 微进度条」表达任务级状态，实测在手机端条高过小、颜色几乎不可辨。现改为**实心高亮条**：条本身就是颜色块，文字直接写在条内，条高约 36rpx，字号 21rpx。颜色只用两种语义——绿=达标、橙=有记录未达标；**不再用条长表达完成度**（完成度进详情看），换取一眼可读的"哪天做了哪件事、做没做到"。
>
> **格子内不使用底色表达日级达标**：一天多计划时"整体是否达标"没有唯一定义，底色保持白/透明两种，只承担"非本月"与"未来"的区分。

#### 6.6.2 规则

- **逐计划渲染**：一个格子内按计划渲染高亮条，只渲染"当日有记录（`day_sum > 0`）"的计划；无记录的计划不占行。
- **状态定义（计划级，不是日级）**：`该计划当日分钟 ≥ 该计划 targetMin` → 达标（绿条）；`0 < 当日分钟 < targetMin` → 有记录未达标（橙条）；`= 0` → 无条。
- **简称规则**：计划名去掉结尾「计划」后取前 2 个字符；不足 2 字则原样显示（「A计划」→「A」，「日语计划」→「日语」，「冲刺计划」→「冲刺」）。
- **排序**：沿用计划列表顺序（置顶计划在前，其余按创建时间）；**最多显示 3 条**，其余折叠为 `+N`（N = 被折叠数量，仅 >3 时出现）。
- **日期数字必须保留**：左上角，任何条数下都不省略；`+N` 在右上角，不与日期数字重叠。
- **月份切换双入口**：顶部 ‹ › 按钮 + 「本月」；同时**整个日历网格支持左右滑动切月**（阈值 ±55px，横向位移需大于纵向 1.5 倍，避免与纵向滚动冲突）。
- **本月定位**：默认打开设备当前月；点「本月」回到当前月并短暂外描边高亮今天。
- 点某日 → 日详情弹层：按计划列出「A计划 30 分钟 · 未达标」「冲刺计划 60 分钟 · 达标」；当天可补录时提供「补录这一天」按钮（多计划时先用 ActionSheet 选计划）。
- 与执行记录（S6）共用同一份 segment 数据，**同一计划当日分钟两处必须一致**。
- 未来日不可补录、不可查看（整格降透明）。

#### 6.6.3 状态矩阵

| 状态 | 表现 |
|---|---|
| 空（该月无任何记录） | 网格内无任何条，只显示日期；统计三格为 0 |
| 有补录 | 含补录格在日期右上角带 10rpx 蓝点 |
| 今天 | 日期数字黑底白字圆形，不影响高亮条 |
| 未来日 | 整格透明度 0.45，不可点 |
| 非本月补位 | 透明底、无日期内容，不可点 |
| **一天多计划混态** | 逐计划出条，一绿一橙同时存在 |
| **一天 4 个计划** | 未达标优先取前 3 条 + 右上「+1」 |
| 窄屏适配 | 7 列等分，条内文字单行省略，不换行、不溢出 |
| 多计划同日 | 逐计划渲染条，**不显示合计分钟**（合计在点开的日详情中） |

## 7. 数据模型

> 本章为字段级定义，供开发与测试对照；不涉及接口协议与代码结构。

### 7.1 存储根对象（v2.1 本地实现）

全部状态存于单个 key `plan_timer_state_v1`（实现见 [store.js](file:///workspace/utils/store.js)）：

```
{
  v: 1,
  plans: [Plan],
  segs: [Segment],
  session: Session | null,
  profile: { nick: string, avatar: string },
  calYM: { y: number, m: number }      // 汇总页记忆的月份（0-based）
}
```

无服务端表、无日汇总表；所有统计在读取时按 `segs` 实时聚合。

### 7.2 Plan

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | string | 唯一 | 时间戳 36 进制 + 随机串 |
| `name` | string | 1–20 字符 | 去首尾空白 |
| `targetMin` | int | `1 ≤ x ≤ 1440`（上限校验待补，见 §12.3 Q8） | 每日目标分钟 |
| `start` / `end` | date | `YYYY-MM-DD`，`end ≥ start` | **含首尾** |
| `targetVersion` | int | 初始 1 | 目标变化时 +1 |
| `changedAt` | date/null | — | 目标变更日，详情页提示用 |
| `pinnedAt` | timestamp/null | — | 置顶时间，倒序排序 |
| `deletedAt` | timestamp/null | — | 软删除，无找回 |
| `createdAt` / `updatedAt` | timestamp | — | 列表排序 |

派生值不落库：`planDays = diffDays(end, start) + 1`，`targetTotal = targetMin × planDays`。

### 7.3 Segment（唯一记账单位）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | string | 唯一 | — |
| `planId` | string | 外键 | — |
| `date` | date | `YYYY-MM-DD` | 计时按**结束当天**归属；补录按所选日期 |
| `min` | int | `≥ 0`；计时 `Math.round(sec/60)`，补录 1–1440 | 整分钟 |
| `source` | enum | `timer` / `manual` | 补录标识来源 |
| `reason` | string | 当前固定 `user_end` | 预留 |
| `startTs` / `endTs` | null | 当前不落具体起止时刻 | 预留 |

**约束**

1. 同一时刻全局最多一个 `session`；进入其他计划的计时页会提示先结束。
2. 本期**不做跨天拆分**，一条片段归属结束日（见 §12.3 Q6）。
3. 累计直接对计划全部片段求和，读取时不再按日期窗口二次过滤（写入入口已受区间约束；极端边界见 §12.3 Q6）。

### 7.4 Session（进行中的计时）

| 字段 | 类型 | 说明 |
|---|---|---|
| `planId` | string | 所属计划 |
| `state` | `running` / `paused` | 运行态 |
| `accruedSec` | number | 已结算秒数（暂停时累加） |
| `startedAt` | timestamp/null | `running` 时本段起点；`paused` 时为 null |

已显示秒数 = `accruedSec + (running ? (Date.now() − startedAt) / 1000 : 0)`。切后台/锁屏/杀进程后重新进入，按该公式自然补足。

### 7.5 计算口径（与 §3 一致，实现锚点）

```
plan_days    = diffDays(end, start) + 1
targetTotal = targetMin × plan_days
completion   = accumulated / targetTotal
active_days  = COUNT(DISTINCT seg.date) where day_sum > 0 且 date ∈ [start, end]
met_days     = COUNT(DISTINCT seg.date) where day_sum ≥ targetMin 且 date ∈ [start, end]
elapsed_days = clamp(diffDays(today, start) + 1, 0, plan_days)
due_min      = elapsed_days × targetMin
gap_min      = max(0, due_min − accumulated)
status       = 未开始   if today < start
               进行中   if start ≤ today ≤ end
               已结束   if today > end 且 accumulated ≥ targetTotal
               已过期   if today > end 且 accumulated < targetTotal
```

### 7.6 补录来源

- `source = manual`，日期限制 `[start, min(today, end)]`，分钟数 1–1440。
- 同一日允许多条，按累加计入；**本期不支持修正或作废已有片段**。
- 补录后完成度、今日数字、执行记录、汇总日历均在下一次 `onShow` 重新聚合刷新。

## 8. 计时状态机与边界规则

### 8.1 状态机

```
         ┌──────────┐   开始    ┌──────────┐   暂停    ┌──────────┐
         │ 无 session│ ────────► │ 计时中    │ ────────► │ 已暂停    │
         └──────────┘           └──────────┘           └──────────┘
                                   │    ▲                    │
                                   │    │ 继续               │ 结束
                                   │    └────────────────────┘
                                   │ 结束
                                   ▼
                            结算为 1 条 segment（source=timer），清空 session
```

- 暂停只冻结秒数（写入 `accruedSec`），**不落库片段**；结束才产生 segment。
- 进入计时页时若存在其他计划的 session，提示「请先结束正在进行的计时」并返回。
- 「开始」按钮仅在无 session 时出现；有 session 时呈现「暂停/结束」或「继续/结束」。

### 8.2 时间基准

- 无服务端校准，统一使用 `Date.now()` 绝对时间戳；用户修改系统时间会如实反映（见 AC-13）。

### 8.3 后台 / 锁屏

- 逻辑层挂起后定时器不跑，但显示值只依赖时间戳；回前台 `onShow` 重算即正确，无心跳、无补偿逻辑。

### 8.4 杀进程 / 长时间后台

- session 已持久化在本地 key 中；重开小程序进入计时页会读回 session，`running` 时按 `startedAt` 补足秒数。
- 本期**不弹结算确认卡**，也不自动按心跳截断（见 §12.3 Q6）。

### 8.5 跨零点

- 本期**不做运行中跨零点拆分**；结束时按结束当天归属，整段计入（见 §12.3 Q6）。

### 8.6 补录

见 §7.6。入口：执行记录视图「＋ 手动补录」、日详情弹层「补录这一天」、计时页「手动补录」。`···` 菜单只承载计划级动作（编辑 / 置顶 / 删除），不放补录。

### 8.7 边界规则汇总（与实现一致）

| 边界 | 实际行为 |
|---|---|
| 跨零点计时 | 不拆分，整段计入结束当天（Q6） |
| 计时中改系统时间 | 显示随系统时间变化；`startedAt` 仍为绝对时间戳 |
| 同一天多次开始/结束 | 多条片段同日，`day_sum` 相加 |
| 单段不足 30 秒 | `Math.round` 为 0 → 提示「不足 1 分钟，本次未计入」，不落库 |
| 计划最后一日跨零点结束 | 片段归属次日；累计不做窗口二次过滤，仍计入（Q6） |
| 达到目标后继续计时 | 允许；超额计入分子；环填满但不变色 |
| 删除计划时有进行中 session | 软删除计划时一并清空该 session |
| 编辑区间导致历史段出窗 | 本期不拦截保存（Q8） |

## 9. 非功能与合规

### 9.1 小程序审核必需项

| 项 | 要求 |
|---|---|
| 用户协议 | 「我的」页可打开，首版上线前必须具备 |
| 隐私政策 | 同上；须声明处理昵称/头像与计时记录，且**仅在本地使用、不上传服务器** |
| 头像/昵称授权 | 仅在用户主动点击时触发；拒绝不影响主流程；界面有默认头像与「点击设置昵称」兜底 |
| 用户隐私保护指引 | mp 后台须勾选「用户信息（微信昵称）」「选中的照片或视频（头像）」，开发者处理方式均选**仅在本地使用** |
| 客服入口 | **v2.1 起不提供**，不配置客服会话，避免审核要求"客服必须可响应"带来的运营负担 |
| 服务类目 | 工具 → 效率，不涉及医疗/教育资质 |

### 9.2 胶囊遮挡

- 全部页面使用**小程序原生导航栏**，胶囊区域由平台保证，业务不在右上角放置任何自绘元素。
- 计划详情的计划级动作 `···` 位于**顶部分段 Tab 行内右端**，与系统胶囊不同层，不存在重叠。
- 汇总页月份切换与「本月」位于导航栏下方内容区，不与胶囊同排。

### 9.3 手势冲突

| 冲突 | 处理 |
|---|---|
| iOS 右滑返回 vs 卡片左滑 | 左滑仅改变卡片 `translateX`（`touchstart/move/end` 自行判定横向位移 > 12px 且大于纵向分量才进入滑动），**不注册系统级手势**，因此与右滑返回不冲突；卡片左滑露出「置顶 / 删除」，删除走确认弹窗 |
| 列表纵向滚动 vs 卡片横滑 | 仅在横向位移大于纵向 1.5 倍时才进入滑动，否则交还给页面滚动 |
| 汇总页纵滚 vs 日历横滑 | 同上策略，阈值 ±55px；纵向位移更大时不切月 |
| 计时页返回 | 计时为独立页面，返回由原生导航栏处理；存在进行中 session 时返回不弹确认（session 保留，可再次进入继续），结束操作才落库 |
| Tab 根 | 不渲染返回按钮，从根上消除"根页带返回"的歧义 |

### 9.4 存储、容量与多用户隔离

**实现（v2.1）**：单一 key `plan_timer_state_v1`，值为 `{v, plans[], segs[], session, profile, calYM}` 的 JSON；读写走 `wx.setStorageSync / getStorageSync`。

| 项 | 结论 |
|---|---|
| 容量上限 | 微信单个 key ≤ 1MB，同一小程序本地缓存上限 10MB |
| 体积估算 | 单片段约 250B；5 计划 × 6 段/天 × 365 天 ≈ 2.7MB/年，仍在单 key 1MB 以下需约 3800 条片段，重度使用约 1.5 年后逼近 |
| 逼近上限时 | 导出备份后清理旧计划；后续版本按 `seg:{planId}:{yyyyMM}` 分片（见 §12.3 Q7） |
| 云端 | **本期无云端、无后端、无账号体系**；数据仅在设备本地 |
| 多用户隔离 | 小程序本地缓存按「小程序 AppID + 微信账号」隔离，同一部手机切换微信账号互不可见；不同用户使用同一账号则共享（符合"同一用户"预期） |
| 换机 | 本地数据不随之迁移，须「我的 → 导出记录」→ 新机「导入记录」 |
| 清缓存 | 微信清理小程序缓存或卸载小程序会丢失数据，隐私政策与「我的」页须明确提示 |

### 9.5 导出格式与现实限制

- 导出格式（v2.1 实现）：**单个 JSON 文件** `plan-timer-{YYYY-MM-DD}.json`，内容为完整 state（`plans` / `segs` / `profile` 等），不做拆分为 `plans.json` + `segments.jsonl`。
- 体积参考：3 年 5 计划约 3MB。
- **限制**：小程序不能直接写入用户文件目录，只能写入 `wx.env.USER_DATA_PATH` 后通过 `wx.shareFileMessage` 交给用户。因此「我的」页文案必须是「导出记录（备份为 JSON 文件）」，**不得写"自动备份/换机一键恢复"**，否则形成错误预期。
- 导入：`wx.chooseMessageFile` 选取聊天中的 JSON；校验 `plans` 与 `segs` 均为数组后弹覆盖确认，确认即整体替换（本期不做字段级合并与去重，见 §12.3 Q4）。

### 9.6 性能

- 计划页首屏渲染 ≤ 300ms（同步读取本地缓存，无网络请求）。
- 汇总页切月 ≤ 150ms（内存中按 segment 现算月视图）。
- 计时页每 500ms 刷新一次文本与 Canvas 环，仅重绘环与两个文本节点。
- 列表/日历均为全量内存计算，未做虚拟列表；计划数 > 50 时再评估分页。

### 10.2 关键指标（观测口径，不含目标值）

1. **建计划完成率** = `plan_create` / 进入表单次数。
2. **计时入口分布** = `timer_start` 按 `entry` 分组，验证「列表 → 详情 → 计时」两跳路径的实际使用。
3. **中断续算比例** = `timer_recover` 次数 / `timer_start` 次数。
4. **补录率** = 含 `manual` 片段的计划数 / 活跃计划数；反映"忘记计时"的普遍程度，决定后续是否做提醒。
5. **删除率** = `plan_delete` / `plan_create`。
6. **数字一致性错误率** = 同一计划同一日在详情与汇总的当日分钟不一致次数 / 总抽样数（应为 0）。

### 12.2 评审重点风险（v2.1 结论）

**R1 · 日期口径的连带一致性（已锁定为含首尾）**
`plan_days = dateDiff + 1`，结束日当天（`date = end`）必须计入统计窗口；`date > end` 的跨天溢出段不再按窗口过滤，仍计入累计（见 §12.3 Q6）。实现见 [calc.js](file:///workspace/utils/calc.js)，AC-04 / AC-10 锁定这两条边界。

**R2 · 辅助指标与主进度的视觉权重（已定稿）**
采用「主进度优先」排版：88rpx 完成度数字在最上，辅助指标「应完成 / 已投入 / 落后」独占其下一行、字号 26rpx。主进度不因辅助指标倒退，`gap = 0` 时显示「已跟上」。实现见 [detail.wxml](file:///workspace/pages/detail/detail.wxml)。

**R3 · 杀进程"诚实结算"的用户信任成本（本期已规避）**
本期不实现心跳结算卡：杀进程后本地 session 保留，重开计时页继续累计，不产生"整夜自动计入"。若后续补心跳结算，需同时解决默认值与确认交互，见 §12.3 Q6。
